# logs/ — Tamper-Evident Archive

Two active subfolders hold the project's log record, with one legacy
archive subfolder for pre-policy items:

- **`confer/`** — confer round logs. Each run has a directory of
  per-round, per-model JSON outputs, plus a `sealed_chain.json` Merkle
  seal produced at the time of archival.
- **`chat/`** — curated chat and conversation artefacts that belong in
  the project record. Populated deliberately, not automatically. Raw
  session transcripts with private user context must not enter here.
- **`_archive/`** — items that predate this two-subfolder policy and do
  not fit either category cleanly. Retained for historical continuity,
  not part of the active record.

## Cryptographic Sealing

Every directory under `confer/` and `chat/` carries a
`sealed_chain.json` file generated by
[`scripts/cdsfl_seal_logs.py`](../scripts/cdsfl_seal_logs.py). The seal
is a tamper-evident Merkle chain (RFC 9162-style, SHA-256 leaves)
produced by [`bench/verification_chain.py`](../bench/verification_chain.py).
Any modification to a sealed file invalidates the Merkle root; the
verifier can then name the tampered leaf.

**Current mode — unsigned Merkle seal.** This provides integrity (tamper
evidence) but not non-repudiation (no digital signature naming a
sealing party). The upgrade path is documented in the docstring of
`cdsfl_seal_logs.py`: supply an Ed25519 signer to `VerificationChain`
and publish the public key at a documented path. The private key must
remain outside the repository.

## Commands

```bash
python3 scripts/cdsfl_seal_logs.py              # seal unsealed directories
python3 scripts/cdsfl_seal_logs.py --dry-run    # show plan
python3 scripts/cdsfl_seal_logs.py --verify     # check existing seals
python3 scripts/cdsfl_seal_logs.py --force      # re-seal everything
```

The verifier is wired into
[`scripts/cdsfl_qc.py`](../scripts/cdsfl_qc.py). If any seal fails
verification, qc reports a `STALE` finding naming the tampered
directory.

## Relationship to bench/logs/

The `bench/logs/` tree remains the operational runtime location for
confer and experiment outputs during bench execution (referenced by
runner scripts and post-processing tools). Its sealing is handled
separately by [`bench/seal_experiment_logs.py`](../bench/seal_experiment_logs.py),
which is scoped to specific experiment subtrees. Both sealing scripts
use the same `VerificationChain` primitive and the same Merkle
semantics, so seals produced by either can be verified by either.
