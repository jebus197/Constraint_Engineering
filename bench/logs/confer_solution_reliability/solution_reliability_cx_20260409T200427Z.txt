## FFAF issues

### Issue 1 — Missing parameter constraint on \(\nu_{\text{eff}}\)
- FIND: \(\nu_{\text{eff}}=\nu_b+(1-S)\nu_f\) can exceed 1 if \(\nu_b+\nu_f>1\).
- FOLLOW: This breaks probabilistic interpretation and can break \(R^+\in[0,1]\).
- ANALYSE: CONFIRMED.
- FIX: Either impose
\[
\nu_b,\nu_f\in[0,1],\ \nu_b+\nu_f\le 1
\]
or reparameterise:
\[
\nu_{\text{eff}}=1-(1-\nu_b)(1-(1-S)\nu_f)
\]
This automatically stays in \([0,1]\).

### Issue 2 — Product form overstates universality
- FIND: \(S=\prod_j v_j\) is only correct if all gates are jointly necessary and each \(v_j\) is a calibrated conditional survival probability.
- FOLLOW: In many domains, some gates are hard admissibility constraints (parse), others are outcome evidence (target resolved), others are collateral-damage checks (regression). Mixing all into one product distorts meaning and cross-domain portability.
- ANALYSE: CONFIRMED.
- FIX: Split:
\[
A=\prod_{j\in \mathcal G_{\text{hard}}} g_j
\]
where \(g_j\in\{0,1\}\) or calibrated \([0,1]\) admissibility gates,
and
\[
E=\text{aggregator}(e_1,\dots,e_m)
\]
for effect evidence.
Then define
\[
S=A\cdot E
\]
This preserves “hard gate veto” while allowing a better efficacy model.

### Issue 3 — Current \(S\) lacks dependency structure
- FIND: target_resolved and regression_free are not independent; regression failures may imply target resolution was illusory or overfit.
- FOLLOW: Product assumes a DAG of conditional factors; no such conditional semantics were defined.
- ANALYSE: CONFIRMED.
- FIX: Use explicit conditional composition or min/gated geometric mean depending on calibration level.

### Issue 4 — Break-even formula depends on chosen \(\nu_{\text{eff}}\) form
- FIND: \(S^*=(\nu_b+\nu_f-qR)/\nu_f\) is valid only for the linear \(\nu_{\text{eff}}\) model.
- FOLLOW: If \(\nu_{\text{eff}}\) is reparameterised to stay bounded, \(S^*\) changes.
- ANALYSE: CONFIRMED.
- FIX: Treat \(S^*\) as model-relative, not invariant.

## 2. Optimal form for solution reliability

## Recommended universal form
Partition verifier outputs into:

### Hard gates
Necessary conditions; failure vetoes the fix.
Examples:
- parses/builds
- schema-valid patch
- proof script type-checks
- dimensional consistency restored

Represent as \(g_j\in\{0,1\}\) or calibrated \([0,1]\).

Evidence the target defect is resolved and collateral damage is absent.

\[

\[

Why this survives:
- hard failures force \(S=0\)
- monotone

- cross-domain

### If you have calibrated conditional probabilities
Then the chain-product
\[
S=\prod_j v_j
\]
is correct, but only with explicit conditional semantics. That is a special case, not the default universal form.

## 4. Tool-verified fix pipeline

Current NL-fix extraction is structurally wrong. The fix artifact must be executable evidence, not prose.

## Required output contract for model-proposed fixes
Each candidate fix should be emitted as a **FixSpec**, not natural language.

### Minimal FixSpec schema
```json
{
  "finding_id": "F123",
  "target_artifacts": ["evidence.py"],
  "edit_script": [
    {
      "op": "replace_function",
      "symbol": "update_reliability",
      "old_hash": "sha256:...",
      "new_code": "def update_reliability(...): ..."
    }
  ],
  "intent": "Ensure ν_eff bounded and tool-derived σ",
  "preconditions": [
    "symbol_exists:update_reliability",
    "ast_parses:true"
  ],
  "expected_local_properties": [
    "sympy_equiv:special_case_S_eq_0",
    "z3:boundedness",
    "pytest:test_targeted_fix_123"
  ],
  "forbidden_regressions": [
    "pytest:full",
    "ruff:all",
    "mypy:pkg",
    "bandit:pkg"
  ],
  "domain_verifier": {
    "type": "python_code"
  }
}
```

### Execution pipeline
1. Parse FixSpec schema.
2. Apply AST-aware edit, not text diff if possible.
3. Run hard gates:
   - AST/parse
   - import/compile
   - schema validity
4. Run targeted verifier for the finding.
5. Run regression suite.
6. Compute \(A,E,S\).
7. Only retain fix candidates with tool evidence attached.

### Why this is better
The output itself becomes machine-checkable evidence. That restores the constraint-box principle for fixes.

## Recommended scoring
For code:
- hard gates:
  - AST parse/build
  - patch applies cleanly to intended symbols
- effect evidence:
  - targeted test resolution
  - regression pass rate
  - static-analysis non-regression
  - optional theorem/property checks via SymPy/z3

Do not let the model score its own fix in prose.

## Experimental arms
Run at least three arms:

### Arm A — Baseline
Current Exp 37 finding pipeline + NL fix extractor.

### Arm B — S_k minimal

### Arm C — S_k split
Executable FixSpec pipeline + \(S=A\cdot E\) and bounded \(\nu_{\text{eff}}\).

This isolates whether improvement comes from better patch representation or better math.

## Per-round loop
1. Models generate findings.
2. Findings canonicalised and confirmed.
3. For confirmed findings only, models emit one or more FixSpecs.
4. Tool executor applies and verifies each candidate.
5. Keep best verified candidate per finding.
6. Update \(R_k\) using observed \(q_k\) and computed \(S_k\).
7. Feed back only tool outputs and updated state.

## Primary metrics
1. **Confirmed defect resolution rate**
   \[
   \frac{\#\text{confirmed findings with verified successful fix}}{\#\text{confirmed findings}}
   \]

2. **Net reliability delta**
   \[
   \Delta R = R_{\text{final}}-R_{\text{initial}}
   \]
   lower is better if \(R\) is residual defect probability.

3. **Fix execution yield**
   schema-valid → applied → targeted-pass → regression-pass funnel.

4. **Bad-fix rate**
   fraction of proposed fixes that introduce regressions or fail target resolution.

5. **Evidence completeness**
   fraction of fixes with full tool trace attached.

## Convergence criteria
Not just “no new findings.” Require both:
1. two consecutive rounds with no new confirmed findings above threshold, and
2. two consecutive rounds with no increase in verified resolved-finding count above threshold.

Also track **solution falsification debt**: confirmed findings with no executable verified fix attempt.

## Success criterion
Experiment 38 succeeds only if it materially improves:
- verified fix yield,
- net resolved defects,
- and final \(R_k\),
without increasing regression rate.

## 7. Distributed compute: more models and topology

## Does R_k need modification for 10 or 20 models?
Yes, at the orchestration level, not necessarily in the per-finding update equation.

Current \(q=\eta d p\) hides correlation. With many models, naive independence assumptions fail hard. More models often increase duplicate findings more than unique signal.

## Necessary extension
Introduce correlation-adjusted effective detection:
\[
q_{\text{eff}} = 1-\prod_{m=1}^M (1-\rho_m q_m)
\]
where \(\rho_m\in[0,1]\) discounts each model’s marginal contribution after overlap/correlation estimation.

Or for exchangeable correlation, simpler:
\[
q_{\text{eff}}=\alpha_M \cdot \max_m q_m + (1-\alpha_M)\cdot\Big(1-\prod_m(1-q_m)\Big)
\]
with \(\alpha_M\) increasing as redundancy rises.

Same issue for fixes: multiple models proposing near-identical patches should not count as independent evidence. \(S_k\) should be computed from tool outcomes of the selected patch, not from number of proposers.

## Topology implications
- **Star/blackboard:** best for canonicalisation and tool grounding. Likely strongest default.
- **Relay:** useful for patch refinement chains, but error propagation risk is high.
- **Mesh:** richer exploration, higher duplicate/correlation burden, more expensive.

Surviving recommendation:
- Use star topology for finding aggregation.
- Use isolated parallel patch generation per confirmed finding.
- Then centralized tool verification.
- Add one adversarial isolated verifier pass on accepted fixes.

R_k/S_k need correlation-aware aggregation upstream, not a topological rewrite of the core state update.
