## FFAFP Findings

### Finding 1: HARD Constraint Monotonicity Violation

**FIND:**
- **Issue:** Domain TOMLs weaken universal HARD constraints without enforcement.
- **Location:** `bench/cdsfl_registry/domains/biology.toml` lines 1-16
- **Evidence:** `[verification]` section sets `hypothesis_test_required = true` but this parameter is SOFT in schema (`constraint_class = "SOFT"` in `schema.toml:verification.hypothesis_test_required`). Domain layer cannot convert SOFT→HARD without monotonicity check.

**FOLLOW:**
- **Dependencies:** All 6 new domain TOMLs (biology, cs_software, information_science, etc.) follow same pattern.
- **Interfaces:** `load_effective_policy()` in `registry.py` merges layers but only checks universal HARDs, not SOFT→HARD elevation.
- **Downstream:** PolicyEngine applies these constraints at runtime. A domain setting `hypothesis_test_required = true` (SOFT) could be overridden by task/model layers to `false`, violating domain intent.

**ANALYSE: CONFIRMED**
- Universal HARDs defined in `registry.py:HARD_CONSTRAINTS`.
- Domain TOML sets SOFT parameter to `true` (tightening), but schema allows lower layers to set to `false`.
- Monotonicity property: lower layers can tighten but never loosen. However, `registry.py:_check_monotonicity()` only checks universal HARDs, not SOFT parameters tightened by domains.

**FIX:**
Extend monotonicity check to track SOFT parameters tightened by higher layers:
```python
# In registry.py, add to _check_monotonicity()
tightened_softs = {
    "verification.hypothesis_test_required": True,  # from biology.toml
    "verification.effect_size_required": True,
    # ... track all SOFTs tightened by domain layer
}
for dotpath, tightened_value in tightened_softs.items():
    actual = _dotpath_get(merged, dotpath)
    if actual is not _MISSING and actual != tightened_value:
        violations.append(f"{dotpath}: domain tightened to {tightened_value}, got {actual}")
```

**P-PASS:**
- **Disproof attempt:** "Domain TOMLs are Layer 2, task/model are Layers 3/4, so tightening at Layer 2 is allowed."
- **Refutation:** CDSFL Directive 2 (Constraint Precedence) requires HARD constraints to take precedence over SOFT. If a domain elevates a SOFT to effectively HARD (by requiring it), lower layers must not weaken it. Current implementation allows weakening.
- **Survival:** Finding survives. System allows task layer to set `hypothesis_test_required = false` despite domain requiring `true`.

### Finding 2: Unknown Domain Fallback Undefined

**FIND:**
- **Issue:** DOMAIN_MAP has no fallback for unknown domains, causing silent degradation.
- **Location:** `bench/cdsfl_registry/registry.py` lines 82-97
- **Evidence:** `DOMAIN_MAP` dictionary maps known domains to TOML files. Unknown domains trigger warning but continue with universal-only policy.

**FOLLOW:**
- **Dependencies:** All experiments with domain not in DOMAIN_MAP.
- **Interfaces:** `load_effective_policy()` → `domain_key = DOMAIN_MAP.get(domain)` returns `None` for unknown.
- **Downstream:** Immune pipeline expects domain-specific configuration. Without domain TOML, verification tools and CT prompts default to universal, potentially missing domain-specific checks.

**ANALYSE: CONFIRMED**
- Unknown domain → warning only → no Layer 2 policy applied.
- Domain-specific verification tools (e.g., `cs_software.toml`'s `test_execution = "mandatory"`) not loaded.
- This is a fail-open (degrade silently) rather than fail-closed (block execution).

**FIX:**
Add explicit fallback domain:
```python
# In registry.py, modify DOMAIN_MAP and load_effective_policy
DOMAIN_MAP = {
    # ... existing mappings
    None: "cross_domain"  # explicit fallback
}

# In load_effective_policy
domain_key = DOMAIN_MAP.get(domain, DOMAIN_MAP[None])
```

**P-PASS:**
- **Disproof attempt:** "Warning is sufficient; operator can see unknown domain warning."
- **Refutation:** CDSFL Directive 4 (Proportionality Gate) requires full falsification for high-consequence assertions. Running experiments with degraded verification is high-consequence.
- **Survival:** Finding survives. Silent degradation violates fail-closed principle.

### Finding 3: HIL Gate Exit Code Propagation Error

**FIND:**
- **Issue:** `launch_exp39.py` exit code 42 on HIL pause, but `run_sequence()` breaks loop incorrectly.
- **Location:** `bench/launch_exp39.py` lines 180-188
- **Evidence:** When `r.hil_paused` is true, loop breaks but `failed_required` set is not cleared. Sequence report shows paused experiment as "failed" in dependency calculations.

**FOLLOW:**
- **Dependencies:** All sub-experiments dependent on HIL-paused experiment.
- **Interfaces:** `run_sequence()` → `failed_required.add(exp.id)` even when `hil_paused`.
- **Downstream:** On resume, dependent experiments may be incorrectly skipped due to `failed_required` set.

**ANALYSE: CONFIRMED**
- Code: `if not r.passed and not r.skipped:` includes `hil_paused` (exit 42 ≠ 0).
- HARD constraint: HIL pause is not failure; must not affect dependency resolution.
- Consequence: Resume may skip valid dependent experiments.

**FIX:**
Modify `run_sequence()`:
```python
# After running sub-experiment
if r.hil_paused:
    # Record but don't mark as failed
    _log(f"\n*** HIL REVIEW GATE: {exp.id} paused ***")
    break
elif not r.passed and not r.skipped:
    if exp.required:
        failed_required.add(exp.id)
```

**P-PASS:**
- **Disproof attempt:** "HIL pause is captured in main() and exits 42 before report."
- **Refutation:** `run_sequence()` returns results list including paused experiment marked as "failed" in `failed_required`. This state persists if bug causes continue past pause.
- **Survival:** Finding survives. State corruption violates data integrity HARD constraint.
