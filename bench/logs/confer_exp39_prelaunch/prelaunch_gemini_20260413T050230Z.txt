### 1. Meta Structured Reasoning Protocol (Premises & Derivations)

**Premise 1 (Policy Enforcement):** The CDSFL methodology mandates that unassessed constraints fail closed (`fail_closed_unassessed`). The registry must enforce domain-specific constraints if a domain is explicitly declared and mapped.
**Derivation 1:** If a mapped domain file is missing, the registry currently skips loading it and silently applies the universal baseline. This is a fail-open condition that bypasses mandatory domain constraints.

**Premise 2 (State Integrity):** A sequential Directed Acyclic Graph (DAG) executor must not inject stateful resume flags into unstarted, state-free nodes.
**Derivation 2:** `launch_exp39.py` applies the `--resume` CLI argument as a global boolean. If a sequence halts at node $N_i$, running with `--resume` applies the flag to $N_{i+1}$, $N_{i+2}$, etc. This commands fresh nodes to resume non-existent states, leading to downstream crash or zombie-state resurrection.

**Premise 3 (Data Provenance):** Scientific benchmarking requires strict alignment between the documented model identity and the executed API endpoint.
**Derivation 3:** `confer_exp39_prelaunch.py` logs operations as `CC2_MODEL = "cc2-opus-4.6"` but hardcodes the subprocess to call `claude-sonnet-4-20250514`. The resulting analytics will falsely attribute Sonnet's performance to Opus.

### 2. FFAFP Execution (Layer 2)

#### Finding 1: Silent Fail-Open in Policy Registry
*   **FIND:** `bench/cdsfl_registry/registry.py`, lines 174–185. If `DOMAIN_MAP` resolves a domain key, but the corresponding `.toml` file does not exist (e.g., `chemistry`), the engine silently falls back to the universal policy without warning.
*   **FOLLOW:** `DOMAIN_MAP` maps `"chemistry": "chemistry"`. The diff introduces biology, cs_software, and information_science TOMLs, but no `chemistry.toml`. When `load_effective_policy("chemistry")` executes, `domain_path.exists()` is `False`. The code skips the merge block and hits no `else` block (the existing `else` belongs to `if domain_key:`). The experiment proceeds entirely stripped of chemistry constraints, violating the `fail_closed_unassessed` HARD constraint.
*   **ANALYSE:** **CONFIRMED** (HARD).
*   **FIX:** Add an explicit failure path for missing mapped files.
    ```python
    if domain_path.exists():
        domain_config = _load_toml(domain_path)
        policy = _deep_merge(policy, domain_config)
        _check_monotonicity(policy, f"domain/{domain_key}")
    else:
        raise FileNotFoundError(f"Mapped domain policy missing: {domain_path}")
    ```
*   **P-PASS:** *Attempted Falsification:* Could a domain be mapped but intentionally lack a file to default to universal? *Refutation:* If a domain requires no overrides, it should not be mapped in `DOMAIN_MAP`; the system's existing `else` block correctly handles unmapped domains by logging a warning and safely defaulting to universal. A mapped but missing file strictly indicates a broken configuration. Fix holds.

#### Finding 2: Global `--resume` Flag Corrupts Fresh Sub-Experiments
*   **FIND:** `bench/launch_exp39.py`, lines 212 and 286. The `--resume` flag is forwarded unconditionally to every sub-experiment evaluated in the `run_sequence` loop.
*   **FOLLOW:** If experiment `39-1` hits the HIL gate (exit 42), the sequence halts. The operator fixes the issue and runs `python3 bench/launch_exp39.py --resume`. The loop restarts. `39-1` is called with `--resume`, successfully loads its checkpoint, and completes. The loop proceeds to `39-2`, calling it with `--resume`. Because `39-2` never started, it possesses no checkpoint. Standard runners fail when asked to resume non-existent states. The entire sequencer topology is corrupted by this stateless flag broadcasting.
*   **ANALYSE:** **CONFIRMED** (HARD).
*   **FIX:** Modify the CLI to target a specific resume ID, or dynamically track which experiment requires resumption. Simplest sufficient correction:
    Change `--resume` to take an ID: `parser.add_argument("--resume-id", ...)`
    In `run_sequence`: `resume_this = (exp.id == args.resume_id)`
    Call: `run_sub_experiment(exp, ..., resume=resume_this)`
*   **P-PASS:** *Attempted Falsification:* What if `reference_runner.py` gracefully ignores `--resume` when no checkpoint exists? *Refutation:* Even if the runner ignores it for missing checkpoints, if a *stale* checkpoint exists from a previous aborted run (not a HIL pause), the global `--resume` flag will inadvertently resurrect that stale state instead of starting fresh. Global resume in a DAG is topologically unsafe. Fix holds.

#### Finding 3: Model Identity Falsification in Pre-Launch Gate
*   **FIND:** `bench/confer_exp39_prelaunch.py`, lines 188-192.
*   **FOLLOW:** The script declares `CC2_MODEL = "cc2-opus-4.6"` (line 59) and lists it in the dispatcher map as `"CC2 (Opus 4.6)"` (line 213). However, `dispatch_cc2` executes `subprocess.run(["claude", "-p", "--model", "claude-sonnet-4-20250514"], ...)`. All output logged and written to the `prelaunch_summary` JSON will be tagged as Opus 4.6 but generated by Sonnet. This contaminates the benchmark provenance.
*   **ANALYSE:** **CONFIRMED** (HARD).
*   **FIX:** Update the subprocess arguments to use the correct Opus model string (e.g., `"claude-opus-2026xxxx"` [VERIFY:current exact CLI model string]).
*   **P-PASS:** *Attempted Falsification:* Could Sonnet be an intentional fallback? *Refutation:* There is no conditional logic indicating a fallback. It is a hardcoded string mismatch. Fix holds.
