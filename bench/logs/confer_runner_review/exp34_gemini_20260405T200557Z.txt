### FINDING_ID: F001
**SEVERITY:** 1.0 (CRITICAL)
**DESCRIPTION:** FIND — The `FindingRegistry` uses a global namespace for model-local finding IDs, causing catastrophic cross-model collisions. In `register()`, `self._alias_map[finding.finding_id] = canonical_id` maps a local ID (e.g., `F001`) to a canonical ID. If Model A files `F001`, it becomes `C0001`. If Model B independently files its own `F001` (a completely different bug), `lookup_alias("F001")` returns `C0001`. The runner then discards Model B's finding and incorrectly records Model B as confirming Model A's finding.
**FOLLOW:** Models frequently use standard sequential IDs (`F001`, `F002`). This collision will silently destroy the majority of novel findings from the second, third, fourth, and fifth models, converting them into false confirmations. The registry state will be entirely corrupted.
**PROPOSED_FIX:** Scope the alias map by model ID.
1. Update `FindingRegistry.__init__`: `self._alias_map: Dict[str, str] = {}`
2. Update `register`: `self._alias_map[f"{model_id}:{finding.finding_id}"] = canonical_id`
3. Update `lookup_alias`: `return self._alias_map.get(f"{model_id}:{model_local_id}")`
4. Update the main loop: `existing = registry.lookup_alias(f.model_id, f.finding_id)`
**VERIFIED:** TRUE
