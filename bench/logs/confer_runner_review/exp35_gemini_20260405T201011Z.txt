### FINDING_ID: F001
**SEVERITY:** 0.9 (CRITICAL)
**DESCRIPTION:** FIND — The `FindingRegistry` uses a single flat dictionary for `_alias_map` keyed only by `finding.finding_id` (e.g., `"F001"`). Because models independently generate their own local IDs (like F001, F002), a local ID from Model B will overwrite the alias mapping for Model A's local ID. 
**FOLLOW:** When Model B submits a new finding "F001", `lookup_alias("F001")` will return the canonical ID of Model A's completely unrelated "F001" from a previous round. The runner will then incorrectly treat Model B's new discovery as a `CONFIRM` verdict for Model A's finding, corrupting the registry state and silently dropping Model B's actual finding.
**PROPOSED_FIX:** FIX — Scope the alias map by `model_id`. 
Change registration to: `self._alias_map[f"{model_id}:{finding.finding_id}"] = canonical_id`
Change lookup to: `def lookup_alias(self, model_id: str, model_local_id: str) -> Optional[str]: return self._alias_map.get(f"{model_id}:{model_local_id}")`
Update the call site: `existing = registry.lookup_alias(f.model_id, f.finding_id)`
**VERIFIED:** TRUE
