## FIX 1: F8 — Merge Quorum

### Claim 1
A merge must never proceed from raw vote count alone; votes must agree on the same merge target.

- Falsifying condition: if two models vote “merge” but specify different targets, and merge still executes safely, then target consensus is unnecessary.
- Attempt to falsify: Round 1 already identified this as a logic bug. Different targets imply incompatible actions; a single merge operation requires one target. No safe interpretation exists without an extra tie-breaker rule.
- Result: provisionally accepted.
- Residual uncertainty: none material.

### Claim 2
A single merge vote can be sufficient only when external model diversity is structurally unavailable and the single vote is strong.

- Falsifying condition: if allowing 1 vote in small panels creates unsafe merges at unacceptable rates, single-vote sufficiency is wrong.
- Attempt to falsify: this is possible in principle, so single-vote must be constrained by panel size and confidence and only used when quorum is impossible, not merely inconvenient.
- Result: accepted with strict floor.
- Residual uncertainty: confidence calibration quality [VERIFY:current].

### Claim 3
The floor should be: never merge with target disagreement; never merge on zero external support; never merge on one low-confidence vote.

- Falsifying condition: if internal/history evidence alone can safely replace external support, zero-support merges might be acceptable.
- Attempt to falsify: no such authority was provided; current system uses model verdicts as merge evidence. So zero external support is too weak.
- Result: accepted.
- Residual uncertainty: whether immune evidence should ever directly support merges [SPECULATIVE]; not needed for minimal design.

## Design

### FLOOR
Merge allowed only if all are true:

1. There is at least 1 external merge vote.
2. All counted merge votes agree on the same target.
3. Either:
   - `distinct_external_models_supporting_same_target >= 2`, or
   - `available_external_models < 2` **and** `distinct_external_models_supporting_same_target == 1` **and** vote confidence is high.

Hard stop otherwise.

### Evidence to inspect
- External-model merge verdicts for this finding in current decision window.
- Proposed merge target per verdict.
- Distinct model IDs.
- Confidence per verdict.
- Count of available external models for this finding/round [VERIFY:current].

### Thresholds
- `HIGH_CONF_MERGE = 0.90` [VERIFY:current]
- “Small panel” = `< 2 available external models`

### CONTEXTUAL RULE
- Default permissive path when evidence is clear:
  - If 2+ distinct external models support the **same** target, allow merge.
- Small-panel exception:
  - If fewer than 2 external models are available, allow merge on 1 vote only if:
    - confidence `>= 0.90`, and
    - no competing merge target exists.

### ESCALATION PATH
Ambiguous evidence => do not merge now.
Cases:
- 2+ merge votes but target disagreement.
- 1 vote only when 2+ external models were available.
- 1 vote in small panel but confidence < 0.90.
- No external votes.

Escalate by:
1. mark finding `merge_contested`
2. defer merge
3. request another round / additional external review if available

### Minimal pseudocode
```python
def can_merge(finding, round_ctx):
    votes = get_external_merge_votes(finding, round_ctx)  # each: model_id, target_id, confidence
    available = count_available_external_models(finding, round_ctx)

    if not votes:
        return DENY("floor:no_external_support")

    by_target = group_by(votes, key=lambda v: v.target_id)
    if len(by_target) > 1:
        return ESCALATE("target_disagreement")

    target_id, target_votes = only_item(by_target)
    distinct_models = count_distinct(target_votes, key=lambda v: v.model_id)
    max_conf = max(v.confidence for v in target_votes)

    if distinct_models >= 2:
        return ALLOW(target_id, "consensus_quorum")

    if available < 2 and distinct_models == 1 and max_conf >= 0.90:
        return ALLOW(target_id, "small_panel_high_conf")

    return ESCALATE("insufficient_merge_quorum")
```

## Design

### FLOOR
Require at least `1` independent external confirmation, excluding the source model, for any confirmation action.

Never below 1.

### Evidence to inspect
- Current finding severity.
- Independent external confirmations in registry.
- Source model attribution.
- Current round index / total rounds or a simple early-vs-late indicator [VERIFY:current].

### Thresholds
Minimal scheme:
- Critical/High: require `2`
- Medium/Low: require `1`
- Early phase: add `+1` only for Critical findings
- Late phase: no reduction below severity rule

So:
- Early + Critical => `3`
- Otherwise Critical/High => `2`
- Medium/Low => `1`

This is intentionally conservative only at the top end.

### CONTEXTUAL RULE
Use stronger measure when stakes/noise are higher:
- If `severity in {CRITICAL, HIGH}`: threshold = 2
- If `severity in {MEDIUM, LOW}`: threshold = 1
- If `phase == EARLY and severity == CRITICAL`: threshold = 3

Use permissive path when evidence is clear and stakes are lower:
- Medium/Low need only 1 independent external confirmation.

### ESCALATION PATH
If confirmations are below threshold:
1. keep finding open/non-terminal
2. route for more review next round
3. if threshold missed by exactly 1 and phase is early, re-check in later round before stronger action

def required_confirmations(finding, round_ctx):

    else:
        req = 1

    if phase == "EARLY" and sev == "CRITICAL":
        req += 1

    return req  # floor already embedded: never < 1

def can_confirm(finding, round_ctx):

        round_ctx=round_ctx,
    )
    req = required_confirmations(finding, round_ctx)

    if len(confirms) >= req:
        return ALLOW(f"met_confirmation_quorum:{req}")
    return ESCALATE(f"need_{req}_have_{len(confirms)}")

## Design

Never allow convergence if:

`active_open_crit_high > cfg.max_open_crit_high_effective`

Where `active_open_crit_high` counts only findings with:
- severity in `{CRITICAL, HIGH}`
- status non-terminal
- not already merged into another finding

### Evidence to inspect
- Finding severity
- Current status
- Whether status is terminal/non-terminal
- Experiment phase

### Thresholds
Minimal dynamic rule:
- Early phase: `effective_max = cfg.max_open_crit_high`
- Late phase: `effective_max = cfg.max_open_crit_high + 1` [SPECULATIVE], capped to avoid unlimited relaxation

Rationale: late phase permissiveness reduces stalls after substantial review, while preserving the hard gate.

If you want even safer minimalism, keep static and only restrict the count to active non-terminals. That is the lower-risk option.

Given Round 1 regression concern, I recommend:
- **Default**: static threshold
- **Optional contextual modulation**: `+1` only in late phase, feature-flagged [VERIFY:current]

### CONTEXTUAL RULE
- Count only active non-terminal critical/high findings.
- Use static cfg threshold by default.
- If phase awareness is desired, only relax by `+1` in late phase after at least one escalation cycle has occurred for the remaining blockers.

### ESCALATION PATH

1. return `BLOCK_CONVERGENCE(open_crit_high_exceeded)`

TERMINAL = {"MERGED", "CLOSED", "REFUTED", "DUPLICATE"}  # UNCONFIRMED handled separately in Fix 4

def active_open_crit_high(findings):
    return [
        f for f in findings
        if f.severity in {"CRITICAL", "HIGH"}
        and f.status not in TERMINAL
        and not is_merged_child(f)
    ]

def effective_max_open_crit_high(cfg, round_ctx, escalation_seen):
    limit = cfg.max_open_crit_high
    if cfg.enable_late_phase_relaxation and experiment_phase(round_ctx) == "LATE" and escalation_seen:
        limit += 1
    return limit

def convergence_gate(findings, cfg, round_ctx, escalation_seen):
    blockers = active_open_crit_high(findings)
    limit = effective_max_open_crit_high(cfg, round_ctx, escalation_seen)

## Design

### FLOOR
For `contested_count`:
- Exclude irrecoverable terminal statuses:
  - `MERGED, CLOSED, REFUTED, DUPLICATE`
- Do **not** lump `UNCONFIRMED` into irrecoverable terminal.

### Correct semantics
Use two counters:

1. `contested_count`:
   - findings still actively disputed / unresolved
   - includes non-terminal statuses only

2. `recoverable_unconfirmed_count`:
   - findings in `UNCONFIRMED`
   - excluded from `contested_count`
   - checked separately before convergence

This keeps semantics clean:
- contested = active dispute now
- unconfirmed = not active dispute now, but still recoverable

### Evidence to inspect
- Status per finding
- Any new evidence since status became `UNCONFIRMED`:
  - newer round timestamp
  - new verdicts
  - immune evidence strings added/changed

### Thresholds
Minimal rule:
- `contested_count` must be `0` for convergence, or whatever existing gate requires.
- `recoverable_unconfirmed_count` does **not** block by itself unless there is newer evidence after unconfirmation.
- If new evidence exists for an UNCONFIRMED finding, reopen/escalate it and treat as contested again.

This is the least disruptive design.

### CONTEXTUAL RULE
- If `UNCONFIRMED` has no newer evidence after terminalization, ignore for `contested_count`.
- If newer evidence exists, it is no longer safely terminal in practice:
  - reopen to active review
  - include in contested handling

### ESCALATION PATH
For each `UNCONFIRMED` finding:
1. compare `status_timestamp` vs latest verdict/evidence timestamp
2. if no newer evidence: leave out of `contested_count`
3. if newer evidence exists: reopen or mark `recheck_required`, and include in next contested evaluation

### Minimal pseudocode

IRRECOVERABLE_TERMINAL = {"MERGED", "CLOSED", "REFUTED", "DUPLICATE"}

def has_new_evidence_since_unconfirmed(finding):

        return False
    return latest_evidence_ts(finding) > finding.status_ts

def contested_count(findings):
    count = 0
    recoverable_unconfirmed = 0
    to_reopen = []

        if f.status in IRRECOVERABLE_TERMINAL:

            recoverable_unconfirmed += 1

                to_reopen.append(f)
            continue

        # all other non-terminal states are actively contested/open
        count += 1

    return {
        "contested_count": count,
        "recoverable_unconfirmed_count": recoverable_unconfirmed,

### FIX 1: F8 — Merge Quorum

**Evidence Inspected:** `votes.target_id` (for agreement), `model_id` (for panel size), `confidence`, `immune_pipeline.verdict`.

1. **THE FLOOR (Hard Constraint):**
   * Target agreement is strictly non-negotiable. If `len(unique(targets_proposed)) > 1`, the merge MUST be rejected. A finding cannot be merged into multiple distinct targets.

2. **THE CONTEXTUAL RULE:**

     * `vote.confidence == HIGH` AND `immune_pipeline.verdict` matches the target signature.
3. **THE ESCALATION PATH:**
   * If target disagreement occurs, reject the merge for the current round, clear the merge votes, and invoke the immune pipeline to generate an `evidence_string` comparing the contested targets for the next round.

def check_merge(votes, panel_size, immune_verdict):

    if count >= 2: return "MERGE"

### FIX 2: F11 — Confirmation Quorum

1. **THE FLOOR (Hard Constraint):**

### FIX 3: F7/F23 — `max_open_crit_high` Convergence Gate

**Evidence Inspected:** `status`, `severity`, `round_timestamps` (duration active).

1. **THE FLOOR (Hard Constraint):**
   * The numerical threshold `max_open_crit_high` must NEVER be dynamically raised to force convergence. Expanding the acceptable number of critical findings just because time has passed compromises the safety gate.
   * Terminal findings (`CLOSED`, `REFUTED`, `MERGED`, `DUPLICATE`) strictly MUST NOT count against this threshold.
2. **THE CONTEXTUAL RULE:**
   * The count must include both `ACTIVE` and `UNCONFIRMED` findings (since an unconfirmed critical is still a critical risk).
   * Instead of changing the threshold, change finding *eligibility*. If a critical finding has been stalled for `> N` rounds and the immune pipeline returns a `low_confidence` verdict, tag it as `EXHAUSTED`. `EXHAUSTED` findings bypass the gate.
3. **THE ESCALATION PATH:**
   * If `open_crit_high > max_open_crit_high` and convergence is blocked, the runner pauses convergence, gathers all blocking findings, and triggers an immediate immune pipeline override. The pipeline must explicitly `REFUTE` or mark `EXHAUSTED`. 

```python
def get_blocking_crit_count(registry, current_round, max_stall_rounds):
    # FLOOR
    terminal_states = {'CLOSED', 'REFUTED', 'MERGED', 'DUPLICATE'}
    blocking_count = 0
    
    for f in registry.get_findings(severity=['CRITICAL', 'HIGH']):
        if f.status in terminal_states: continue
        
        # CONTEXTUAL
        age = current_round - f.created_round
        if age > max_stall_rounds and f.immune_verdict == 'LOW_CONF':
            f.set_tag('EXHAUSTED')
            continue
            
        blocking_count += 1
        
    return blocking_count
```

### FIX 4: F14/F17/F22 — Terminal Status in `contested_count`

**Evidence Inspected:** `status`, `round_timestamps`.

1. **THE FLOOR (Hard Constraint):**
   * `MERGED`, `CLOSED`, `REFUTED`, and `DUPLICATE` are mathematically irrecoverable in the current execution graph. They MUST be excluded from `contested_count`. 
2. **THE CONTEXTUAL RULE:**
   * `UNCONFIRMED` is conditionally recoverable and directly impacts convergence.
   * If `current_round - created_round < GRACE_PERIOD` (e.g., 2 rounds), it is actively awaiting review. Include it in `contested_count` (prevents premature convergence).
   * If it exceeds the grace period without confirmation, it is functionally dead. Exclude it from `contested_count` (prevents the Exp 37 stall).
3. **THE ESCALATION PATH:**
   * When an `UNCONFIRMED` finding ages out of the `contested_count`, do not delete it. Transition it to a dedicated `ORPHANED` status. If new evidence (a delayed model vote) arrives targeting an `ORPHANED` finding, immediately reopen it and re-increment the `contested_count`.

```python
def calculate_contested(registry, current_round, grace_period=2):
    # FLOOR
    irrecoverable = {'MERGED', 'CLOSED', 'REFUTED', 'DUPLICATE', 'ORPHANED'}
    contested = 0
    
    for f in registry.get_all():
        if f.status in irrecoverable: 
            continue
            
        # CONTEXTUAL
        if f.status == 'UNCONFIRMED':
            age = current_round - f.created_round
            if age >= grace_period:
                f.status = 'ORPHANED' # Escalation path preserves it
                continue
                
        contested += 1
        
    return contested
```
