### FIND-FOLLOW-ANALYSE-FIX (FFAF)

**ISSUE 1: AST Parse Vulnerability to Hallucinated Null Bytes**
- **FIND:** In `_run_hard_gate_ast`, the `try/except` block only catches `SyntaxError`. If an LLM hallucinates an invalid encoding or null bytes (`\x00`) inside a `REPLACE` block, `ast.parse` throws a `ValueError` (`source code string cannot contain null bytes`).
- **FOLLOW:** Unhandled `ValueError` in `_run_hard_gate_ast` $\rightarrow$ unhandled exception in `compute_sk` $\rightarrow$ unhandled exception in `_evaluate_sk_for_findings` $\rightarrow$ the runner's main loop crashes entirely, terminating the experiment prematurely.
- **ANALYSE:** CONFIRMED. Constraint: HARD (System Execution Safety).
- **FIX:** Expand the `except` tuple to catch `(SyntaxError, ValueError)`.

**ISSUE 2: Type Safety for Extracted Meta Parameters**
- **FIND:** In `_evaluate_sk_for_findings`, the parameters `nu_b, nu_f, q, R_old` are extracted via `meta.get("key", default)`. If the upstream LLM regex parser leaked a string due to formatting anomalies (e.g., `"0.05"` instead of `0.05`), passing these to `compute_rk` triggers `max(0.0, min(1.0, "0.05"))`, which throws a `TypeError`.
- **FOLLOW:** Upstream string leak $\rightarrow$ `TypeError` in `min()` boundary clamping $\rightarrow$ S* computation aborts $\rightarrow$ runner crashes.
- **ANALYSE:** CONFIRMED. Constraint: HARD (System Execution Safety).
- **FIX:** Explicitly cast inputs to `float()` at the entry points of `compute_rk` and `check_sk_threshold`, with a safe fallback to `0.0` to guarantee math operability.

### FALSIFICATION (P-PASS REVIEW)

**FALSIFIER:** The implementation of $S^*$ clamping (`max(0.0, min(1.0, s_star))`) masks regimes where the baseline re-injection ($\nu_b$) exceeds the detection benefit ($q \cdot R$), which theoretically results in an $S^*$ threshold $> 1.0$ (i.e., NO fix is safe). By clamping to $1.0$, a perfect fix ($S_k = 1.0$) would pass the threshold check, violating the rule that no fix is safe.
**ATTEMPT:** I mathematically constructed the break-even limit. If $\nu_b > \frac{R_{\text{old}} - R_{\text{det}}}{1 - R_{\text{det}}}$, even $S_k=1.0$ introduces more risk than leaving the flaw alone. If the model computes $S^* = 1.2$, clamping it to $1.0$ makes $S_k \ge 1.0$ evaluate to `True`.
**RESULT:** Claim falsified but practically superseded. The domain specification actively bounds expected $\nu_b$ to `0.02-0.10`. For $S^*$ to naturally exceed $1.0$, the baseline re-injection would have to be catastrophically high while detection capability ($q \cdot R$) is near zero. Furthermore, if $S_k = 1.0$ passes in this extreme edge-case, it strictly means the tools verified 100% of claims with zero regressions, making the theoretical harm purely statistical. The clamping behavior is safe and operationally intended.
