### QUESTION 1 — Domain-Agnostic FFAFP Gate Redesign

#### P-Pass Analysis
**Initial Claim:** Gate 2 checks "diff size" and Gate 3 evaluates "code modifications."
**Falsifier:** In formal mathematics, adding a single logical negation (`~`) has a near-zero "diff size" but maximally alters the semantic state space (inverts the theorem). Code modifications are inapplicable to claims of statistical significance where the output is a set of probabilities, not source code.
**Revision:** The gates must evaluate *mechanical validity*, *semantic magnitude*, and *independent consistency*, entirely decoupled from source-code string operations.

#### Abstract Gate Interface Data Structure
```python
@dataclass
class GateResult:
    passed: bool
    confidence: float          # 0.0 to 1.0
    falsification_debt: float  # Residual risk
    evidence: Dict[str, Any]   # Domain-specific payload (e.g., proof tree, residuals)

class IFalsificationGate(Protocol):
    def evaluate(self, claim: Claim, context: DomainContext) -> GateResult: ...
```

#### Domain-Agnostic Contract & Implementations

**Gate 1: Mechanical Validity (G1)**
*Abstract Contract:* Does the claim satisfy the deterministic, syntactical, or physical conservation laws of its domain?
- **Software:** AST is well-formed, tests compile, exit code `0`.
- **Mathematics:** Symbolic expression parses, type-checking passes, theorem provers (SymPy/z3) return `sat` or `True`.
- **Statistics:** Matrices are invertible, degrees of freedom > 0, assumptions for specific test (e.g., normality) mechanically evaluated.
- **Physics:** Dimensional homogeneity holds (LHS units == RHS units), fundamental conservation laws (energy, momentum) are not violated.

**Gate 2: Semantic Delta / State Space Impact (G2)**
*Abstract Contract:* What is the mathematical or logical magnitude of the proposed change relative to the baseline? (Replaces "diff size").
- **Software:** Cyclomatic complexity delta, API boundary modification count, structural AST diff.
- **Mathematics:** Change in logical dependency depth, alteration of boundary conditions in a proof.
- **Statistics:** Effect size (Cohen's $d$, odds ratio), change in $R^2$ or Information Criterion (AIC/BIC delta).
- **Physics:** Magnitude of energy state change, phase transition boundary shift, order-of-magnitude perturbation.

**Gate 3: Cross-Validation / Adversarial Consistency (G3)**
*Abstract Contract:* Does the claim survive evaluation by a secondary, orthogonal, or adversarial evaluation method? (Replaces "code modification check").
- **Software:** Mutation testing (did changing the code fail the test?), static security analysis.
- **Mathematics:** If G1 used symbolic proof, G3 uses Monte Carlo numerical evaluation across the domain space to find counterexamples.
- **Statistics:** Out-of-sample validation, bootstrap resampling stability, cross-validation scoring.
- **Physics:** Independent numerical simulation (e.g., finite element analysis vs analytical solution), boundary condition limit testing.

**Definitive Stance:** The 3-gate FFAFP architecture must immediately transition from `[Execution, Syntax Diff, Commit Analysis]` to `[Mechanical Validity, Semantic Delta, Adversarial Consistency]`. Code execution is merely the software-domain implementation of G1.
