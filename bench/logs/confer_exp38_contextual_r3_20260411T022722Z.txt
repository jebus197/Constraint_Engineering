Here is the review of the 4 contextual decision implementations under the Find-Follow-Fix framework. 

### 1. F8 — Contextual Merge Quorum: Local Panel Size Bypass
- **FIND:** `available_external` is calculated from `entry["verdicts"]` (models that have already voted on this specific finding), rather than the global number of models on the panel.
- **FOLLOW:** Early in a round, the first external model to vote MERGE will make `len(available_external) == 1`. The logic will misidentify the run as a "small panel" and execute the merge immediately. This completely bypasses the quorum requirement on large panels, allowing premature convergence and violating FLOOR SAFETY.
- **FIX:** Calculate `available_external` using the global configuration of the runner (e.g., total configured external models), not the finding's local verdict list.
- **Severity:** CRITICAL

### 2. F8 — Contextual Merge Quorum: Null Target Corruption
- **FIND:** If all MERGE verdicts lack a regex-matched target, `target_id` evaluates to `"__unknown__"`. The logic proceeds into the consensus block and executes `registry.resolve(..., merged_into=None)`.
- **FOLLOW:** This reintroduces the exact mechanical bug F8 was meant to fix. The finding is merged without a valid target, permanently dropping the finding into a corrupted state.
- **FIX:** Treat `"__unknown__"` as an invalid target state. If consensus centers on `"__unknown__"`, do not merge. Defer the decision or escalate to HIL.
- **Severity:** HIGH

### 3. F11 — Severity Quorum: Small Panel Stalling
- **FIND:** Critical/High findings (`sev >= 0.7`) strictly require 2 independent confirmations, with no awareness of the total available panel size.
- **FOLLOW:** If the runner is operating a globally small panel with only 1 external model, critical findings will never reach the 2-confirmation threshold. They will stall indefinitely, permanently preventing legitimate convergence.
- **FIX:** Cap the required quorum by the globally available external model count: `required = 2 if (sev >= 0.7 and global_external_models >= 2) else 1`.
- **Severity:** HIGH

### 4. F7/F23 — EXHAUSTED Bypass: Unreviewed Finding Evasion
- **FIND:** The EXHAUSTED bypass only checks the finding's age (`current_round - last_status_change_round >= threshold`) without verifying if the finding has actually been reviewed by the panel.
- **FOLLOW:** A critical finding that is simply backlogged or ignored by the models for 8 rounds will be silently flagged EXHAUSTED and excluded from the gate count. The runner will converge while bypassing entirely unreviewed critical issues, causing a massive Floor Safety failure.
- **FIX:** Require at least one verdict to trigger the EXHAUSTED state: `if age >= exhausted_round_threshold and len(e.get("verdicts", [])) > 0:`.
- **Severity:** CRITICAL

### 5. F14/F17/F22 & F7/F23 — Getters Mutating State & Cross-Gate Contradiction
- **FIND:** Both `contested_count` and `open_crit_high_count` mutate finding state (`e["status"] = "OPEN"` and `e["exhausted"] = True`) from inside counting getter functions. Furthermore, because `exhausted` is evaluated inside the `open_crit_high` getter, `contested_count` remains unaware of it. 
- **FOLLOW:** Calling these metric functions for logging, dry-runs, or dashboard rendering will unpredictably trigger permanent state transitions outside the core `_update_finding_statuses` lifecycle loop. Additionally, if an EXHAUSTED finding has unresolved challenges, it bypasses the `open_crit_high` gate but still trips the `contested` gate, preventing the convergence the bypass was explicitly designed to allow.
- **FIX:** Move the logic that transitions UNCONFIRMED to OPEN and sets the `exhausted` flag into the main `_update_finding_statuses` mutation loop. Update both getter functions to strictly read state (`if e.get("exhausted"): continue`).
- **Severity:** CRITICAL
