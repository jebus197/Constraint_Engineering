## Disposition for Experiment 32

Exp 32 is a meta-experiment where models analyse convergence data — not a code review. The fixes that matter for Exp 32 are **infrastructure fixes** that affect how the experimental harness behaves. Code-level bugs in the reviewed files affect the NEXT code review experiment (Exp 33), not Exp 32 itself.

## CC2 Multi-Agent Architecture: Option A (Runner-Side Parallelism)

For the next code review experiment, CC2 will use runner-side parallelism rather than CC2-internal agent spawning. This means the runner dispatches 3-4 parallel prompts to CC2 with specialist roles, then merges their outputs before passing to the immune pipeline.

Advantages:
- Full audit trail: every prompt and response logged by the runner
- No opaque internal agent state
- Runner controls context budget per sub-agent
- Existing immune pipeline handles deduplication across sub-agents

Implementation notes:
- CC2 entry in MODEL_CONFIGS gets a `parallel_agents` parameter (default 3)
- Each sub-agent gets a specialist role suffix: structural, semantic, integration
- Runner dispatches in parallel, collects responses, merges into single CC2 response
- Finding IDs prefixed: CC2a_F001, CC2b_F001, CC2c_F001
- Immune pipeline deduplicates across sub-agents same as across models
