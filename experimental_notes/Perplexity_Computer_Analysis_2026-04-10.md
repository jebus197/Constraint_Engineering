# Perplexity Computer vs CDSFL — Competitive Analysis

**Date:** 10 April 2026
**Trigger:** Founder flagged Perplexity Computer as potential overlap
**Method:** Web research + dispassionate analysis + extrapolation

## Summary

Perplexity Computer (launched Feb 2026, $200/month) is a multi-model orchestration platform coordinating 19 frontier models. Its verification mechanism is **Model Council**: 3 models → synthesiser → consensus answer. CDSFL operates at a fundamentally different layer — structured Popperian falsification with multi-cell immune verification, mathematical grounding tools, and quantitative convergence metrics.

**Assessment:** Not a competitive threat. A validation of the multi-model premise with a gap in the verification layer.

## Overlap

| Capability | Perplexity Computer | CDSFL |
|-----------|-------------------|-------|
| Multi-model orchestration | 19 models, auto-routing | 5 models, star topology |
| Task decomposition | Sub-agents per subtask | Burst phases per code section |
| Cross-model comparison | Model Council (3-way consensus) | Multi-round panel with convergence |
| Specialist routing | "Right model for each step" | Domain cells + capability fingerprints |

## What CDSFL does that Perplexity doesn't

1. **Falsification, not consensus** — Perplexity asks "do 3 models agree?" CDSFL asks "can we break this?" Perplexity's own data: 37% hallucination rate on citations.
2. **Multi-cell immune verification** — 6 cell types with distinct tools vs 1 synthesiser model
3. **Mathematical verification** — z3, SymPy, AST grounding vs "do models agree on the math"
4. **Convergence metrics** — ρ, γ, open_ch, contested vs one-shot delivery
5. **S_k pipeline** — sandbox fix evaluation with hard gates vs no structured reliability assessment
6. **Finding registry with status FSM** — auditable evidence chain vs finished answer
7. **Autoimmune prevention** — Regulatory T cell prevents over-rejection

## What Perplexity does that CDSFL doesn't

1. **Consumer UX** — product vs research methodology
2. **Scale** — 400+ integrations, enterprise features
3. **Speed for general tasks** — one-shot is faster when "close enough" is fine
4. **Business model** — paying customers vs methodology + evidence

## What CDSFL can learn

1. Multi-model bet **validated commercially** — external confirmation of core hypothesis
2. Model Council = simplified CDSFL without iteration/falsification/tools — shows ceiling of consensus-only (37% hallucination)
3. Synthesiser is **single point of failure** — like Helper T without B-Cell/NK/RT
4. **UX matters for adoption** — Phase D more urgent
5. Task decomposition with model routing = burst mode — confirms direction

## Extrapolation

- **Generalises:** consensus ≠ correctness applies to ALL multi-model systems
- **Boundary:** CDSFL advantage holds where correctness is non-negotiable (STEM, safety, legal, medical)
- **Testable:** Does multi-round falsification measurably outperform single-round consensus? [Bench Run 2]

## Key Analogy

Perplexity Computer = asking three doctors for an opinion and picking the consensus.
CDSFL = running a clinical trial.
Both use multiple doctors. Only one has a protocol for detecting when all three are wrong.
