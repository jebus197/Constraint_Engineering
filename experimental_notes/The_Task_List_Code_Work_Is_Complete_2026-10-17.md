# The task list's code work is complete, and what remains needs a run or a ruling

Written 2026-10-17, 19:45 BST, under CDSFL note standard v1.7. Branch `sim/shakedown-2026-09-29`, HEAD `27a2a853`.

## What this records

The master task list stood at 18 open entries this afternoon. It now stands at 10, and all 10 are waiting either on an experimental run or on a decision that is the founder's to take. No remaining entry is waiting on code that could be written without 1 of those 2 things. The register of issues, which the founder asked to be built and then asked to be populated with the project's whole history, now holds 2,610 tickets covering all 1,701 commits made since the project opened on 12 March 2026.

This note states what was closed, what is left, what each remaining item needs, and the measurements that decided several questions differently from the way they had been planned.

## What closed, and on what evidence

8 entries closed. Each names a test file as its evidence, and a guard refuses any entry marked complete whose named evidence is not a test the suite actually runs.

**C2, the 3 counting mistakes.** A new module, `bench/counting.py`, gives the project 1 place to count things. Its `unit` argument is keyword-only and has no default, so a figure carries its unit out of the function rather than losing it. Self-exclusion is the default, because a script searching for a term will itself contain that term, and the excluded paths are returned rather than silently dropped so a reader can object to them.

**C9, the human-review switch.** The founder asked what effect the `hil_review` facility would have. The answer is that it is a mid-run halt rather than a review step: both call sites in each live runner terminate the experiment's own runner process with exit code 42 after writing a partial report. It therefore sits at neither of the boundaries the founder reviews, which are the input and the output. Turning it on converts 1 autonomous run into N sequential sessions, and the rounds after an intervention are not the same process as the rounds before, so a convergence figure spanning an intervention is not a measurement of autonomous convergence. Autonomous convergence is this programme's success criterion. No shipped configuration enables the switch, and no archived run has ever paused.

**C6, the skipped tests.** The founder asked on 5 October whether 12 skipped tests were safe to ignore. Nothing had answered it and no script existed that could. There are 472 places in the suite where a skip can occur, across 232 files, but a place where a skip can occur is not a skip. Over the subset of tests that runs before every commit and refuses it when any fails, the live figure is 1,171 passed and 0 skipped. The classifier that sorts skip reasons treats an unrecognised reason as its own category rather than as safe, because a classifier that defaults the unknown to safe reports that everything is fine whatever it is given.

**C7, the routing ladder.** The founder ruled on 5 October that the ladder should be a measured statistic and not a list of vendor names. The order cannot be measured from the archive: the omnibus test rejects the hypothesis that the seats are equal, so they really do differ, but none of the 10 pairwise orderings survives correction for multiple comparisons, and a ranking is a set of pairwise orderings. The substantive finding is worse than that. The live panel roster uses short keys, cx, cgpt, ge, ds, cc2, fable and kimi, while the order holds vendor names, Codex, CC2, ChatGPT, Gemini, DeepSeek and Fable. Not 1 roster key matches, so the ladder returns the roster unchanged: reverse the input and the ranking reverses with it. It looks like a ranking and is an identity function. Behaviour was deliberately left unchanged, because matching case-insensitively would reorder the live panel and reordering the rungs of a falsification ladder changes which seat is asked first. What changed is that each routing pass now records whether its order rested on measurement and how many seats the order actually ranked, and both figures travel into the run's own artefact.

**B17, making recovery mechanical.** The founder asked why, if compaction can be detected mechanically, the recovery cannot also run mechanically. 2 of its 3 parts already did: the compaction hook runs `rs`, the project's restore-state command, and a second hook refuses to end the turn so that restore lands. The third that did not is that a hook cannot make an assistant open the documents a notice names. On 16 October the notice supplied 10 file paths, the recovery ran, and the session still spent hours recovering. The open work is now injected inline on the first post-compaction turn. The size was measured before the shape was chosen: the full list is 654,237 characters, the open entries capped at 90 characters each cost 2,009, at 120 they cost 2,639, with their ruling state at 110 they cost 2,828, and the identifiers alone cost 97. The shape carrying the ruling state was chosen, because that field is what separates a decision the founder has already given from a question he is owed. The live brief measures 2,627 characters. The logic lives in the repository rather than in the hook, because a hook in a home directory is unversioned and exists on 1 machine.

**A19, scoring a computable fragment inside prose.** The per-fix half was built in the morning. The last named sub-part was per-hunk classification, for a fix carrying several edit blocks that do not all touch the same kind of thing. Of 25,445 fix texts in the archive, 13,219 parse as exactly 1 edit block, 12,226 parse as none, and 0 parse as more than 1. Among the parseable patches that is 13,219 of 13,219 single-block. Per-hunk and per-fix therefore give the same answer for every patch that exists, so the sub-part is covered by construction rather than deferred by judgement, and a test fails the moment a 2-block fix appears.

**B11 and C29, the board and the burndown.** C29 had claimed the task list could no longer be said to terminate. It can. The branching figure is 0.7381 new entries per entry closed, with a 95 per cent interval from 0.5651 to 0.9641 and an exact test against 1 giving a probability of 0.0152. The list is subcritical and terminates. C29 had asked for a ruling on whether to raise the bar for what becomes an entry, which would lower that figure by changing the policy rather than the work. That ruling is no longer needed, because the record terminates under the complete-recording policy, so the founder is not asked to trade completeness for a number.

**B23, the backfill.** All 1,701 commits reachable from the current branch are now in the register, each raised and then closed, with no row absorbed into an existing ticket. This was the last item on the list and the founder asked for it to be left until last.

## 3 findings that changed the plan rather than following it

**The attached design brief was right about the thing that mattered.** The founder forwarded a design brief from Gemini Web with the caution that it is an unbound model carrying none of this project's constraints. Its proposal of a relational table with an indexed primary key for exact lookups would have bought nothing: the existing exact lookup is a dictionary at 0.0015 milliseconds and the hashed similarity tier runs at 0.0328 milliseconds. Its proposal of an inverted text index was correct, and would have been dismissed by reasoning alone. The word-overlap layer cost 27.7689 milliseconds on the mean, with a 95 per cent interval from 24.1092 to 31.4286, because it compared against every ticket. An in-memory index was built instead of the proposed full-text virtual table, because the register already loads wholly into memory and a second copy on disk can drift from the append-only log. It gives the same answer 200 times out of 200 and runs 203 times faster.

That decision then earned itself. After the backfill tripled the register, the linear search costs 480.4354 milliseconds per query, with an interval from 452.0338 to 508.8369, against 5.8033 milliseconds for the indexed path. Without the index, every duplicate check after the backfill would have taken half a second.

**Wiring the policy engine as planned would have truncated the experiments.** The plan for B21 said that wiring the policy merge into the runner was the single change that makes everything else declarative, and that it was a handful of lines. The merged policy for the mathematics domain has 46 leaf values, and exactly 1 shares a name with a runner configuration field. That value conflicts: the runner's default is 21 rounds and the policy says 5. Across 47 shipped configurations, none leaves the field unset, so the runner's default is dead and the configurations always decide; their values are 2, 6, 8, 10, 12, 15, 16, 20 and 29, and none is 5. Letting the policy decide would cap 46 of the 47 below their configured round count. The real question is which layer owns that quantity, and it is the founder's, because each answer has a different consequence for replaying the archive. The safe half of B21, a preflight check that refuses a run whose policy layers do not merge, is built and lands green over 17 layers.

**The register refused its own author, 3 times, and was right each time.** It refused a rejection, on the ground that only the founder may reject a proposal and a model declining its own suggestion is not a ruling. It refused a restatement that would have moved a hashed identity. And it refused a commit in which 2 entries had been closed in the task list while their register tickets stayed open, catching the disagreement as 134 closed against the list's 136.

It also lost a proposal, which was a real defect and is fixed. A genuinely new feature request was not created: the register handed back a settled ticket because the 2 shared exactly 1 code identifier. 2 repairs were tried and both were refuted before the third was accepted. Requiring the word layer to corroborate a shared identifier is circular, because that tier exists to catch rewordings the word layer misses, and the suite proved it by falling from 4 of 4 to 1 of 4 on the known rediscovery cases. Requiring a partial vocabulary overlap would have separated the cases, but only by a margin of 0.0318 fitted to 5 data points, which is a tuned constant pretending to be a finding. The accepted repair leaves the decision alone and fixes the loss: an absorbed proposal's own words are now recorded on the ticket that absorbed it, and are reachable by an opt-in search.

## Defects found in the author's own instruments

7 predicates written during this work returned a wrong answer and were caught before any figure reached the founder. 3 are worth recording because each looked like a clean result.

A measurement of fix texts used 5 to 7 angle brackets as the edit-block marker where the real marker is 4. It reported 0 single-block and 0 multi-block fixes across 25,445 texts. A predicate that returns 0 for everything is indistinguishable from the finding it is looking for.

A counter of how many seats the routing order matched folded letter case while the ranking it was describing does not. It reported 2 matches of 7 seats where the ranking itself matched 0 of 7. Both implementations were individually consistent, so neither could be found by reading it; they were found by executing both and comparing.

The skip survey itself reported a clean result from a dead process. Its subprocess produced no output at all, which yields no skip reports, and the script printed that nothing had been skipped and called it the strongest possible answer. It now refuses to draw any conclusion from a run whose summary it cannot read, and 2 tests drive both a killed run and a completed run, because 0 skips and a crash are otherwise indistinguishable.

A guard in the suite also failed for a reason that had nothing to do with the property it guards: it read a fixed window of 1,100 characters of source and checked for key names in the text, and a comment added nearby pushed a key past the cut. That file already recorded the same failure twice for a third test, which had been converted to parse the syntax tree, so the lesson had been applied to 1 of 3 tests. Both remaining tests now parse, which is also stricter: a key named only in a comment used to satisfy the window and now fails.

Finally, 3 commits failed for an operational mistake. Each was launched in the background while editing continued, including editing the pre-commit hook itself. A shell reads a script incrementally, so the running hook read modified bytes mid-execution and died. The hook was never broken; the concurrency was.

## The 10 entries still open, what each needs, and the proposed fix

None of these is waiting on code that can be written without a run or a ruling.

**R1. Restart experiment 53, the zero-plant control.** Ruled twice, on 7 August and again on 6 September. Needs a run. No decision outstanding.

**C4. The owed free-panel run.** This is the only remaining entry carrying no ruling, and it is an instruction rather than a decision: a panel review was directed and has not been held. Needs a run on free seats.

**C12, C15, C18 and C21.** All 4 are built and tested, and all 4 wait on a run to confirm them: a free-panel check, a simulated run, a panel reading, and a cold-start knockout respectively.

**B13. Admitting a model is not trivial, and the cost is silent defaulting.** Putting a model that does not exist through the real resolution chain shows that of 7 steps, 5 default silently and only 2 fail loudly. A researcher who misses 1 table gets a seat that runs while losing whatever that table gated. The proposed fix is to make a missing registration fail loudly at dispatch first and to consolidate to a single registration point second, in that order, because a single point that still defaults silently would hide many misses behind 1. The decision that is the founder's is whether the loud failure should be a raised error, a refusal to dispatch that seat, or a run-level preflight, because it changes how every seat is configured. It was put to the free panel on 16 October.

**B21. Making model and role selection trivial.** Step 4, the preflight validator, is built. Step 1 is not a wiring task but the ownership question described above. Steps 2, 3 and 5 depend on the answers to B13 and to step 1, and the founder directed that they go to the free panel on design, implementation and integration with the coming interface build.

**B22. What a fix means outside code.** The founder directed this to a free panel, asking not only whether the harness is already a general-purpose instrument for science but what would bring it meaningfully closer. The evidence that should travel with the brief is already assembled: the policy layer holds 10 domains rather than 1, the ground-truth corpus holds 5 independently written documents with 29 tagged claims and a runnable falsifier each, and all 3 shakedown legs ran as a mathematics domain against prose and converged. Against that, the canonical runner makes no call to the policy merge engine, so nothing domain-adaptive reaches a live run.

**C1. The claim channel's promotion.** The founder asked for this to be implemented and tested. The measurement his gate required now exists. The channel transcribes the falsifier path rather than judging claims, so its own error is transcription error: it transcribed 58 of 58 verdicts exactly, bounding that error below about 6.2 per cent, and all 4 of its routing properties hold. The falsifier path itself discriminated in both directions on 5 of 5 documents. What remains is not measurement but form: the channel is not wired into the scoring equations and no document specifies how it would enter them, as a weight, a multiplier, a gate or a term. Clearing the flag without that form would stop the code describing itself truthfully while changing nothing, and then invent a model term to make it true. That form is the founder's decision.
