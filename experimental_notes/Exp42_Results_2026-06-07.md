## 3. HIL-legitimacy analysis (the founder's question)

**Recovered HIL-escalation categories** (`rg` over directive/docs/memory): fixes touching **safety or core-functionality** (fixes HIL-gated, never auto-applied — human signs off each with bug+fix+tests+consequence map, `feedback_fixes_hil_only`); **irreconcilable panel disagreement** (defer-on-deadlock, EXTENDED_RATIONALE); **UNCERTAIN** verdicts (asymmetric thresholds → HIL); **CONTESTED-persistent**; **CC2v ESCALATE**; **CLOSED→REOPEN on new evidence** (ARCHITECTURE.md:46). Standing principle: **minimal HIL, one definitive recommendation, never a buffet** (`feedback_hil_fatigue`).

**Verdict: the 15 escalations are AVOIDABLE, not legitimate.** None is a safety call, a core-functionality decision, or a genuine panel disagreement. They are **real bugs the panel should have resolved itself** but could not, because (a) its falsifier *code* was mechanically broken (8/15), (b) no falsifier was written (7/15), or (c) severity was inflated on latent bugs (9/15). They reach HIL at the *is-it-real?* stage — a question the panel should answer with a working test — rather than at the legitimate *should-we-apply-this-fix?* stage. **This is a new issue (falsifier-code quality + severity calibration), not the HIL queue working as designed.**

**Caveat (honest exception):** the audit's `genuinely_hard_to_falsify` category (real defect, no deterministic test — e.g. concurrency/timing) **did not occur in this run** (0/15). For other targets it could, and those *would* be legitimate minimal-HIL-impossible events. So minimal HIL is achievable on this target, with that exception held open for code where it is not.

## 4. Recommended fixes (for the experiment-plan review — not yet applied)

1. **Falsifier-harness hardening** — run falsifiers from repo root (kills the `sys.path`/CWD class for free) + inject standard import scaffolding. Rescues ~half the buggy-falsifier ERRORs with no model change.
2. **Falsifier-debug retry** — on an ERROR verdict, feed the runner's stderr back to the model to fix its own test (same pattern as the DeepSeek `_falsifier_format_repair`, applied to ERROR not just missing). Would convert real-defect-with-buggy-test → CONFIRMED/REFUTED.
3. **Severity calibration** — directive nudge: latent/conditional defects rate below the 0.7 critical threshold unless they fire on real inputs. Removes 9/15 from the convergence-blocking set.
4. **Convergence-policy decision (founder)** — should a real-but-latent, genuinely-un-falsifiable defect *block* convergence (current A4), or be triaged to HIL-without-blocking? Genuine design call.
