PART 1. YOUR 4 QUESTIONS, ANSWERED FIRST

Is the blocked run simulated or real. Simulated. Its own log says so on its first line, and all 6 of its seats are simulation seats. No money was spent and none would be spent re-running it. What it costs is machine time, and the figure is large: the original run took 342.1 minutes.

Will the re-run use the old severity measure. Yes, the current gate, and that is the right choice for a reason stronger than caution. The run is simulated, and the run's own log records that in a simulated run the severity magnitudes are uncalibrated against a real panel and do not transfer. So a severity design cannot be validated on this run even in principle. Testing a new severity rule there would produce a number that means nothing outside the simulation.

When will the new severity design first be used. There is no date, because what blocks it is a build and not a schedule. What severity IS has been settled: 2 independent panel seats both found that your definition is what the mathematical model already calls R sub k, its residual risk term, and both found it should gate convergence as an added 4th condition rather than replacing any part of the existing gate. What is missing is the difficulty term. I measured it again today rather than relying on the panel: the per finding parameter block is present on 0 of 3,256 archived entries, a 95 per cent interval of 0 to 0.001178, so the difficulty value never arrives and the code falls back to a fixed default every time. Until that term is written, R sub k carries no difficulty signal at all, which is exactly the 4 plus 4 against Riemann contrast you drew.

What will its real world impact be. 4 things, each measured rather than asserted. To begin with, it can only ever make convergence harder. It is an added condition, so it can hold a run open longer but can never close a run sooner. Second, today it would decide almost nothing, because with the difficulty term defaulted that term has almost no spread: the panel measured the old form at exactly 0.5 for all 1,252 entries it examined, and the new form spanning only 0.3667 to 0.5 with 59.3 per cent of entries sitting on the floor. A condition that is nearly constant is not a decision. Third, once the difficulty term is written the impact is real and is about floors. The floor is derivable, and I rechecked it today on 3 tools: the composite update has exactly 2 fixed points, 1 and the re injection rate divided by the detection power, and the second is the one the recursion actually reaches. In plain terms, residual risk cannot be driven below the re injection figure divided by the detection figure, and a worked case makes it concrete: at a 5 per cent chance that a fix introduces a new flaw and a 20 per cent chance of catching a flaw that is there, the floor is 25 per cent and not 5 per cent. The appendix previously stated the floor as the re injection rate alone, and a solver confirms that form can never be the higher of the 2, so the old statement was always optimistic. Fourth, the boundary cannot be a universal constant, which both seats found independently, so each experiment will need its own derived bound and the reporting has to carry it.

A separate mechanism is routinely confused with the above, and it is not the route. There is a separate flag that promotes an appendix section from shadow to deciding. It is not the new design and it should not be switched on. Measured: it is inert for convergence, because the series it feeds reads the raw severity and comes out byte identical with the flag on or off, and it is actively harmful at one fail safe, because it makes the severity half of a release condition constant true and so releases a proven unresolved critical finding from the one guard meant to hold it. Both panel seats refused it independently and by different arguments.
